# Internationalisation de la landing (FR/AR)

## Vue d'ensemble

La landing publique (`/`, `/cabinets-comptables`) existe en français et en arabe
(`/ar`, `/ar/cabinets-comptables`). L'ERP, l'authentification et la rue virtuelle
restent en français.

- **Dictionnaires typés** : tout le texte visible vit dans
  `src/app/features/home/content/` (`landing-copy.types.ts` décrit l'arbre
  `LandingCopy = { locale, shared, home, cabinets, contact, seo }`). Le FR
  (`landing-copy.fr.ts`) est importé statiquement ; l'AR (`landing-copy.ar.ts`)
  n'est chargé que par `import()` paresseux (chunk `landing-copy.ar-*.js`,
  absent d'`index.html`). `satisfies LandingCopy` rend toute clé FR manquante
  en AR bloquante à la compilation.
- **Locale** : `LandingLocaleService` pose `html[lang][dir]` et
  `body.landing-rtl` ; seul écrivain. `localStorage['instafact_landing_locale']`
  n'est qu'une indication — jamais de redirection automatique.
- **RTL** : Bootstrap RTL **5.1.3** (même version que la LTR vendeur) chargé à la
  place de la LTR par `HomeThemeService`, surcharges Chain dans
  `src/landing-rtl.scss` (bundle non injecté `landing-rtl.css`, chargé par
  `HomeThemeService` en AR uniquement), propriétés CSS logiques dans tous les
  composants, police **Noto Sans Arabic** (OFL, auto-hébergée,
  `assets/fonts/noto-sans-arabic/`, sous-ensemble arabic via `unicode-range`).
- **SEO** : canonical par langue, `hreflang` `fr-TN`/`ar-TN`/`x-default`,
  `og:locale` + `og:locale:alternate`, `inLanguage` dans le JSON-LD,
  sitemap avec alternates `xhtml:link`.

## Ajouter ou modifier une clé de texte

1. Ajouter la clé au type (`landing-copy.types.ts`) avec sa limite de longueur en JSDoc.
2. Renseigner le FR (`content/fr/<zone>.ts`).
3. Renseigner l'AR (`content/ar/<zone>.ts`) — en branche, un `// TODO-AR` avec la
   valeur FR est toléré ; la parité complète (TD7) l'interdit en production.
4. Aucune chaîne visible dans les templates (y compris `aria-label`, `alt`,
   `title`, `placeholder`) — `npm run check:landing-copy` échoue sinon.
5. Emphase inline : `**gras**`, `_italique_`, `[[latin]]` via `LandingCopyService.rich()`
   et `<app-landing-rich>` ; jamais de HTML dans les dictionnaires.
6. Nombres/prix : jamais dans les dictionnaires — `landing-pricing.ts` et les
   constantes, injectés par `format()` dans des `<span dir="ltr">`.

## Ajouter une langue

1. Étendre `LandingLocale`, `LANDING_DIR`, `LANDING_LANG_TAG`, `LANDING_PREFIX`.
2. Créer `content/<locale>/` + `landing-copy.<locale>.ts` (`satisfies LandingCopy`).
3. Ajouter le chargement paresseux dans `LandingCopyService.ensureLoaded()`.
4. Montage de route dans `home.routes.ts` (miroir de `ar`).
5. Police dédiée si l'écriture l'exige (font-face + préchargement AR dans
   `HomeThemeService`).

## Règles typographiques AR

- Chiffres occidentaux partout ; montants « 49 د.ت » (nombre en `dir="ltr"`).
- Sigles latins conservés : TEJ, NCT, InstaFact, PDF, XML, API ; TVA/CNSS/DGI/NIF/IRPP
  traduits avec le sigle latin entre parenthèses à la première occurrence.
- Ponctuation arabe (، ؛ ؟), guillemets « », texte impératif à l'infinitif.
- Longueurs : viser ≤ FR × 1,3 (les limites JSDoc des types FR s'appliquent à l'AR).
- Terminologie : voir `docs/landing/ar-glossary.md` (source importée par le test de
  parité ; termes bannis : « إنستافاكت », « الضريبة على القيمة المضافة », « العميل »).

## Revue du texte arabe (porte de production)

1. `node scripts/export-landing-copy-review.mjs` génère `docs/landing/ar-copy-review.md`
   (tableau Clé | FR | AR | Statut | Commentaire).
2. Le client valide chaque ligne (« Validé ») — 100 % requis avant activation.
3. Activation : `environment.prod.ts` → `landing.arabicEnabled: true` (PR d'une ligne).
   La même PR ajoute les `<url>` arabes (`/ar`, `/ar/cabinets-comptables`) au
   `src/sitemap.xml` avec les alternates `ar-TN` — tant que l'arabe est désactivé,
   le sitemap reste FR seul pour ne pas référencer des pages qui redirigent.
4. Captures de référence RTL dans `docs/screenshots/landing/ar/`.

## Rollback

`environment.landing.arabicEnabled = false` → build : le sélecteur disparaît,
`/ar/**` redirige vers l'équivalent FR, plus de `hreflang ar-TN`, ni `landing-rtl.css`,
ni polices arabes chargées. Aucun fichier à supprimer.

## Vérifications

```bash
npm run test:landing        # check:landing-copy + check:landing-css
npx ng test --watch=false --browsers=ChromeHeadless \
  --include='src/app/features/home/**/*.spec.ts' \
  --include='src/app/core/services/landing-*.spec.ts'
npx ng build --configuration production   # landing-rtl.css + chunk landing-copy.ar-*.js
npx playwright test e2e/landing-i18n.spec.ts
```
